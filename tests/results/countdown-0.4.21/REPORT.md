## Reading the display

1. Beside the existing candle-state badge above the chart, read **Closes in MM:SS** for5m/15m or **HH:MM:SS** for1h/4h. Narrow screens wrap the adjacent group without horizontal scrolling. It stays outside Display and remains visible when manual price bounds hide the tiny axis text.
2. Read **Last server-offset estimate** or **Local-clock estimate** and the separate **Feed:** status. The former reuses the last trusted server offset, which may be old; the latter has no server alignment. Neither promises timing accuracy or a healthy feed. Stale, disconnected and offline labels remain explicit beside a retained estimate.
3. At the scheduled boundary, an unconfirmed candle shows **Awaiting close update**. An already closed latest source candle shows **Awaiting next candle** until an actual next candle arrives. Missing/loading data shows **Awaiting candle data**; invalid input/clock or clock before candle is explicitly unavailable. No modulo wrap, negative countdown or invented next candle.
4. Click or keyboard-open the countdown summary for selected source/product/symbol/timeframe, exclusive scheduled boundary and estimated clock in UTC, plus limitations. Details retain open state and focus during updates; there is no per-second live region, flashing, sound or saved preference.

Clock time never marks a candle closed, creates the next candle, analyzes a decision, writes a journal record or emits an alert. Existing source data/confirmation policy remains authoritative; REST/source-confirmed candles without a developing candle also wait for the next candle. This is schedule context, not exchange acknowledgement, a tick quote or a trading signal.

## Exact timing and source binding

`candleCountdown()` reads only the latest selected-context `S.k` candle and existing `regionalClock()`/`feedHealth()` projections. It validates current product/symbol/supported timeframe, valid source OHLCV/closed state, safe dates and positive step. Exclusive scheduled boundary is **t+TFMS[tf]**, independent of inclusive `end=t+step−1`. During `t≤now<boundary`, seconds are **ceil((boundary−now)/1000)**. Thus1ms remains00:01 (or00:00:01 on hourly frames), rather than a premature0:00. For now≥boundary, wait for source confirmation; now<t is unavailable. Closed source state is never changed by this projection.

Draw derives this projection once and passes the same result to the toolbar and retained price-axis text. Short axis states are `Await close`, `Closed` (corresponding to Awaiting next candle), `Waiting` or `Unavailable`. The existing axis position and last-price geometry are retained. A local absolute clock/time jump or resumed tab derives afresh; there is no decrement accumulator, catch-up replay or added clock. Chart timezone, hover, history, panning, journal selection and Candles/Line do not change its source.

Only preexisting named function `draw()` changes; existing anonymous details-toggle handling additionally schedules a redraw for the new details so chart coordinates resize promptly. New helpers are read-only projection/DOM updates. `regionalClock`, feed/clock trust, routing/reconnect/source guards, indicators/strategy/selection/backtest/plans/costs/sizing, journal/export algorithms and rule/execution/RSI versions remain exact.
