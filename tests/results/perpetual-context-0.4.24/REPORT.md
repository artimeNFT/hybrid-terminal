## Sources, units and qualifications

Official Binance documentation inspected2026-11-04: [market-data API](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/market-data), [USDⓈ-M contract quantity definitions](https://www.binance.com/en-AE/support/faq/detail/360033161972). Native underlying-asset quantity follows the USD-M contract convention and current exchangeInfo baseAsset/quoteAsset/marginAsset/PERPETUAL identity; it is not inferred from price, quantity precision or notional division. USD-M endpoint field descriptions do not themselves repeat a unit tag, so the product/unit qualification is explicit and restricted to the three supported USDT perpetuals. Metadata ambiguity/failure leaves OI and its comparison unavailable.

Each manual batch uses **at most7 public GETs**, below the8-request ceiling. First `/fapi/v1/time` fixes the batch history qualification cutoff; then6 independent requests: exchangeInfo, premiumIndex, fundingRate, openInterest, openInterestHist and ticker/bookTicker. Existing jsonFetch12-second request timeout/cancellation is reused, without another scheduler/timer. No pagination or automatic retry; failures are per endpoint and never affect the candle feed. The nominal sequential bound is12s time request +12s concurrent remainder, excluding browser scheduling.

| Metric | Source / qualification |
| --- | --- |
| Mark, Index, gap | Same-symbol premiumIndex; positive finite prices. Gap=`10000*(mark/index−1)` bps. Not the exchange's official premium index. |
| Settled funding | fundingRate history, limit5/endTime=batch cutoff. Valid signed finite rates, matching symbol, nonfuture timestamps and ordered distinct (time,type) records. Latest qualified timestamp is shown; simultaneous returned types stay separate, never summed. Regular/Special and absent legacy type are distinguished; unsupported types remain unavailable. Percent per settlement event, not APR. Associated Mark and all raw type fields retained. No fixed funding calendar. |
| Next funding | Separate nextFundingTime from premiumIndex; scheduled future time at capture, not a confirmed payment. Raw lastFundingRate is not the settled metric. |
| Current OI | openInterest with verified USD-M metadata; native BTC/ETH/SOL quantity, including a genuine zero. Its own exchange time is retained; it is not a current notional or a chart-candle value. |
| Historical5m OI change | openInterestHist period5m/limit2/endTime at the completed5m boundary. Exactly two ordered same-symbol/same-unit records, consecutive period-end timestamps300000ms apart and not future to the server cutoff. `100*(end−start)/start`, positive finite denominator and finite result. No notional-value substitution or gap fill; unavailable independently of current OI. |
| Bid/ask/spread | Same-symbol bookTicker; positive ordered quotes. Spread=`10000*(ask−bid)/((ask+bid)/2)` bps with finite arithmetic. Equal quotes legitimately give0. RPI orders are excluded by this endpoint; no executable fill or complete round-trip-cost guarantee. |

Every field carries product/symbol/unit/endpoint, qualified source time where supplied and device receipt time. Shared response timestamps are displayed together without merging different endpoint observations. Missing source times remain UNKNOWN; they are never filled from receipt time. Network failures have separate failedAt and no invented data receipt. Exact fields, raw references and formulas are expandable. Captured values have fixed timestamps, no permanent LIVE/FRESH claim, and no reconstruction at confirmed decision time. No account/API key, probability, recommendation, funding-PnL or liquidation model.
